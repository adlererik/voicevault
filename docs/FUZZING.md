# What the lab fuzzes

VoiceVault uses **coverage-guided mutation fuzzing**. `cargo-fuzz` builds a Rust entry point for each target with libFuzzer coverage instrumentation and AddressSanitizer. LibFuzzer starts with example inputs, mutates them, runs the target and keeps inputs that add coverage or other interesting execution features. Randomness helps choose mutations. The harness determines what those bytes mean and which security rules are checked. [LLVM libFuzzer documentation](https://llvm.org/docs/LibFuzzer.html) · [Rust Fuzz Book](https://rust-fuzz.github.io/book/cargo-fuzz/setup.html)

Several targets build a valid session or a signed message before applying changes. That matters because an attacker controlling a phone can manipulate ciphertext, while a malicious contact with valid session keys can send correctly authenticated garbage. Arbitrary ciphertext mostly exercises the outer parser and authentication checks. For example, `record` uses test session keys to encrypt a chosen counter, type and payload, then feeds the result to the real receive path twice. It separately submits raw bytes to the same receiver. Test identities and fixture entropy are public and reproducible. [Record harness](../fuzz/fuzz_targets/record.rs) · [Fixture record helper](../crates/protocol/src/fixtures.rs)

## The eight targets

| Target | What the fuzzer controls | What the harness checks |
|---|---|---|
| [`handshake`](../fuzz/fuzz_targets/handshake.rs) | An even first byte sends the entire input to the responder as the first hybrid message. The other branch completes the genuine first message, then uses groups of three bytes as a 16-bit offset and an XOR mask for the responder's genuine reply. | Executes the real hybrid receiver with raw and tampered inputs under instrumentation. The harness allows either return value. Specific rejection and downgrade rules are asserted separately in [`hybrid.rs`](../crates/protocol/tests/hybrid.rs). |
| [`record`](../fuzz/fuzz_targets/record.rs) | Controls whether the fixture call is active. Supplies an authenticated record with either a small or arbitrary 64-bit counter, a type from 0 through 8, and up to 102 payload bytes. Also supplies a raw record. | Exercises receipt before and after call activation, authenticated malformed records and duplicate delivery by submitting the same record twice. The harness allows either receive result. Exact replay, consent and counter behavior is asserted in the [protocol tests](../crates/protocol/tests/security.rs). |
| [`codec`](../fuzz/fuzz_targets/codec.rs) | Supplies a complete candidate Opus packet and up to four successive chunks of at most 102 bytes to the same decoder. Seeds include SILK, CELT and multi-frame examples. | Exercises the size, channel and duration checks, actual Opus decode for admitted packets, and concealment after the packet sequence. Decode errors are expected inputs. Audio fidelity is checked separately against [reference Opus](RESULTS.md). |
| [`enrollment`](../fuzz/fuzz_targets/enrollment.rs) | Selects one of three Noise XX enrollment messages or the first encrypted fingerprint confirmation, then applies offset and mask pairs. | A failed read must prevent that side from finishing enrollment, and a failed confirmation must prevent completion. If both sides finish, their fingerprints must match and the installed contact records must match the expected peer. |
| [`lifecycle`](../fuzz/fuzz_targets/lifecycle.rs) | Alters a genuine signed invitation and an authenticated contact snapshot after setting up pinned contacts, protected storage and a fixed trusted clock. | Only the unchanged invitation may be accepted. A rejected invitation must leave the protected generation unchanged and must leave the genuine offer usable. An accepted offer must reject replay. The changed snapshot must be rejected and the genuine snapshot must still restore. |
| [`update-radio`](../fuzz/fuzz_targets/update_radio.rs) | Feeds raw update bytes and edits a correctly signed envelope. Independently submits radio commands in chunks of up to 40 bytes and chooses when to reset or pop the queue. | A changed signed envelope must fail verification. The radio queue must stay within its bound. A controller reset must leave the locally selected offline-update mode in force, so radio data remains refused. Flash power cuts are covered by [separate lifecycle tests](../crates/protocol/tests/lifecycle.rs). |
| [`hybrid-kem`](../fuzz/fuzz_targets/hybrid_kem.rs) | Sends a constructed 1,184-byte ML-KEM public key, zero-filling any bytes absent from the fuzz input, or applies offset and mask groups to the 1,088-byte KEM ciphertext inside an authenticated handshake. | Exercises key validation with a peer whose outer handshake authentication is valid. The public-key branch allows either return value. The ciphertext branch asserts that effective ciphertext changes cause key confirmation and session creation to fail. It requires an unchanged ciphertext to succeed. |
| [`startup`](../fuzz/fuzz_targets/startup.rs) | Chooses a flight, advances a simulated clock and submits variable-length fragment bytes. A separate path supplies the complete set of correctly formed fragments for one of the two hybrid flights. | Any emitted flight must have the exact size for its role and fit the fixed buffer. The valid sequence is checked for byte equality if the parser returns a result. The [link unit tests](../crates/link/src/lib.rs) explicitly require completion, including with reversed fragment order, and cover expiry and work limits. |

## Running and reading the results

`./lab test` runs the suite locally. `./lab watch` runs the same checks and displays reported fuzz activity at [the loopback dashboard](http://127.0.0.1:8765/). GitHub holds the [target source](../fuzz/fuzz_targets/), [initial corpora](../fuzz/corpus/), [runner](../scripts/lab.py) and [committed results from the local run](evidence/hybrid-v2/). The repository has no GitHub Actions fuzz workflow. The published result is a record of that specific local run.

The runner uses nightly `2026-08-21` and copies each checked-in corpus to a fresh run directory. Each campaign uses seed `870321`, a 120-second time budget, a five-second input timeout and a configured input cap of 4,096 bytes for `handshake`, `hybrid-kem` and `startup`, or 512 bytes for the other targets. A pass requires a successful exit and a report of at least 120 seconds. The copied corpora and any failure artifacts stay under that run's `fuzz/` directory. The first line in each log shows the exact invocation. Keep a failing input for replay with the same target and toolchain. Time-based runs can produce different counts even with the same seed. [Toolchain setup](DEVELOPMENT.md) · [Runner source](../scripts/lab.py)

In the hybrid v2 run, all eight targets ran for 121 seconds each. LibFuzzer reported 3,519,377 executions, of which 3,360,300 came from the startup fragment parser. The authenticated KEM target performed 6,442 executions because it builds real cryptographic exchanges. These numbers count target invocations, including repeated inputs and quick rejections. They give a sense of throughput. They do not quantify unique attacks, percentage of project code covered, or confidence against an adversary. [Recorded per-target counts and raw logs](evidence/hybrid-v2/#instrumented-fuzzing)

The raw handshake campaign started with a 48-byte example and finished with an 80-byte mutation limit, below the 1,248-byte initiator message, despite the higher configured cap. Its second branch still mutated a genuine 1,152-byte response on each invocation of that branch. Separate tests mutate every byte position of both full-size messages and verify rejection, including genuine and padded legacy handshake attempts. The startup fuzzer's checked-in seed is three bytes, so its large count should not stand in for adversarial testing of fully formed fragment sequences. [Handshake log](evidence/hybrid-v2/logs/fuzz-handshake.log) · [Full-size and downgrade tests](../crates/protocol/tests/hybrid.rs)

Before committing to a board, prioritize full-size handshake seeds and structured fragment sequences with valid packets mixed with loss, duplication, reordering and expiry. Add assertions for replay-window integrity and refusal before consent on the authenticated-record path. Run longer campaigns with several seeds, retain minimized regressions and report coverage by protocol function or state transition. Keep known-answer tests, explicit attack scenarios and bounded proofs alongside fuzzing. Real BLE and microSD drivers, hardware side channels and fault behavior require their own tests.
