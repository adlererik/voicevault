# Quietlink Lab threat model

## Attacker and exclusions

The target adversary has NSA-class resources: both phones are already fully compromised, including through zero-day/zero-click exploitation, and the adversary controls the telecommunications links and cooperating relays. The model starts after phone compromise; it does not try to prevent Pegasus or emulate its exploit chain. Both phones may collude and manipulate every byte they forward.

**Supply-chain attacks are excluded at the project owner's request.** The endpoint software, device-local UI/clock/entropy, provisioning trust anchors, and initial manufacturing are trusted assumptions. Physical extraction, invasive fault attacks, malicious manufacturing, and compromised endpoint firmware are not demonstrated defenses of this software model. Boot, storage and update fault tests still model important device-local failure behavior.

The desired property is confidentiality and authenticated audio between independently verified trusted endpoints despite hostile transport, under the stated cryptographic and implementation assumptions. No result is a claim of being “NSA-proof.” The attacker can always deny service and observe call timing, duration, transport identity/location and traffic correlation. A compromised phone with an intact microphone can record nearby speech independently of encryption.

The trusted side consists of the supervisor's synthetic local UI, the two endpoint processes, and their implementation and dependencies. The supervisor provides public contact records and the expected signer keys over separate local control datagrams that the phones and relay never inherit. Each endpoint generates its signing and static DH secrets locally. The host OS, launcher, dynamic loader, and executable before seccomp installation are part of the trusted computing base.

The two phones and relay can see the direction, timing, size, and public counters of ciphertext records, as well as link framing and call start and stop. They can cooperate, drop or withhold all traffic, or substitute, duplicate, reorder, delay, and corrupt datagrams. They cannot grant consent through the media interface. The virtual tests exercise these faults against the same endpoint state, record parser, reassembler, and Opus wrapper used in the wall-clock run. The wall-clock tests exercise real process boundaries and actual nonblocking kernel backpressure. Availability and resistance to traffic analysis beyond the fixed active-slot record size are outside the guarantee.

## Pairing, calls, and record handling

The implemented Noise XX enrollment exchanges signed contact records, checks their binding to Noise static keys, displays the full 256-bit transcript fingerprint, and requires local comparison approval and encrypted confirmation from each device. A six-digit SAS is not implemented. The native five-process experiment instead uses a trusted supervisor to model an already verified out-of-band enrollment; the complete XX ceremony is tested separately.

The contact record holds a 32-byte Ed25519 verifying key, a separate 32-byte X25519 public key, and a 64-byte Ed25519 signature over both keys with a contact-specific domain. Verify the signature against the expected out-of-band signer before creating a pin. In a hardware deployment the independent identity verification step would need an authenticated physical or human channel.

Signed 128-byte invitations bind sender and recipient keys, a recipient boot challenge, strictly increasing persisted contact counters, trusted-clock expiry and a fresh call nonce. Only verified invitations supply a trusted display name. Offer and acceptance are bound into the Noise prologue; incoming signaling alone cannot grant local consent. Signature verification work has a bounded admission budget.

Noise KK uses the accepted invitation transcript and the pinned static keys. The resolver supplies a fresh OS-random block exactly once for each wall-clock ephemeral key. The deterministic scenarios use named fixture seeds. The two Noise handshake messages have empty payloads. Each direction uses its own Noise split key in stateless transport. The first eight wire bytes are the little-endian nonce sequence. The remaining 120 bytes carry a 104-byte encrypted body and 16-byte tag. The body has a type, a length, bounded payload, and zero padding. Changing the public counter changes the AEAD nonce and invalidates the tag.

Encrypted sequence 0 confirms local consent. Sequence 1 acknowledges that both confirmations are in place. Media starts at sequence 2 and follows the absolute slot number, allowing gaps. Send and receive state use one shared 64-slot replay policy per incoming direction with separate state for each call. Unauthenticated input, out-of-range media, and unsupported commands cannot advance the replay window. Opus payload framing and duration checks run after authentication. Startup control traffic withheld or delivered out of order causes the call to fail. Recovery after a failed start or process reset requires a new handshake. Media keys stop at 15,000 local 20 ms slots (five minutes); this version stops rather than implementing seamless ratcheting. Session close is irreversible and drops its owned zeroizing transport-key objects. Long-term identity and storage keys use zeroizing owners. Snow internal KDF/stack temporaries and complete memory-remanence behavior remain an erasure-review gap; forward secrecy is conditional on proper erasure, not an extraction-tested claim.

## Linux worker policy

The Linux x86-64 forwarder starts with an empty environment. It uses connected nonblocking Unix datagram sockets on descriptors 0 and 1. The launcher sets a finite kernel send buffer. Before polling, the child closes descriptors 2 and above, enables `PR_SET_NO_NEW_PRIVS`, installs a default-EPERM seccomp BPF policy, and runs escape probes. Failure stops forwarding and the endpoint startup times out. The filter checks the x86-64 audit architecture and matches exact syscall numbers, including the absence of the x32 ABI bit.

The allowed operations are `poll`, `clock_gettime`, `rt_sigreturn`, `exit`, `exit_group`, and connected `sendto` / `recvfrom`. The last two are restricted to descriptors 0 and 1, null address pointers, zero flags, and at most 39 bytes including the receiver's oversize sentinel. Other operations, including file open, `socket`, `connect`, `ptrace`, `process_vm_readv`, descriptor duplication, and ancillary descriptor transfer, receive EPERM. The test checks the denies against a live endpoint process and verifies that a probe still crosses its two inherited sockets. Worker startup and its kernel/loader rely on the trusted executable. Arbitrary hostile code can consume CPU within the host's scheduler policy. Endpoint work stays bounded per slot, and blocked IPC remains nonblocking. [Linux seccomp filter documentation](https://www.kernel.org/doc/html/latest/userspace-api/seccomp_filter.html)

## Audio and validation scope

The endpoint profile is mono Opus at 16 kHz, 320 samples per slot, 24 kbit/s CBR, no FEC, and DTX disabled. Encoded silence uses the same 60-byte Opus packet budget. Mute and encoder underrun use encrypted filler. Fragments carry at most 32 bytes of a record, with at most eight incomplete assemblies and a three-tick lifetime. The receive jitter buffer has eight positions and nominal four-slot playout delay. It uses Opus PLC for missing or malformed frames and outputs silence for authenticated filler. A scheduling gap can drop playout ticks, leaving zero samples at those positions in the WAV.

The harness exercises published Cacophony KK and XX vectors through the actual selected secret-owning resolver, including directional stateless transport. Decoder conformance checks all 12 RFC 8251 vectors with the upstream quality comparator at the lab output rate and channel count, accepting either of the two RFC reference decodes as the upstream harness does. The vector harness exercises valid Opus modes and geometries beyond the narrower wire profile. Four Kani harnesses check the actual replay bitmap, bounded consent/confirmation transitions, closed-call irreversibility and a monotonic security counter. They do not verify AEAD, the complete update path, the kernel or all possible application behavior. Snow, Opus, the kernel and the full process graph are exercised by the runtime tests. [Noise test-vector format](https://github.com/noiseprotocol/noise_wiki/wiki/Test-vectors) · [Opus test vectors](https://opus-codec.org/testvectors/)

Separate hardware validation would measure worst-case MCU timing and memory with real capture, playback, and interrupt loads. It would test BLE MTU negotiation, connection intervals, fragmentation, RF retries, reconnect behavior, and observable radio timing. Acoustic work would measure microphone and speaker leakage, mute behavior, echo paths, and the device's power and RF side channels. The software lab reports digital playout timing and synthetic WAV direction only.

## Device-local lifecycle boundaries

Contacts occupy eight fixed slots. ChaCha20-Poly1305 seals owner-bound snapshots; a protected monotonically increasing generation supplies the nonce and rollback floor. Revocation and invitation counters survive modeled snapshot restoration. `StorageRoot` is an in-memory secure-element abstraction, not a chip driver. Retaining its protected state across a simulated reboot is an assumption. Losing the latest snapshot fails closed and can lose availability. Secure-element endurance, transactions and actual persistent atomicity are not demonstrated.

The radio controller is treated as hostile. Its sole accepted data command carries 6–38 link bytes, with eight queue slots, a per-tick work budget and expiration. No wire command grants UI consent or access to entropy, clock, contacts, flash or debug. Reset cannot clear rate limits or leave local offline-update mode. Native ingress uses this same bounded port before reassembly. Memory/MPU/DMA isolation of a real radio is future hardware work.

The offline update model accepts a raw signed envelope only after a local action. Ed25519 authenticates a versioned target, security version, exact length and BLAKE2s payload digest. A modeled immutable verifier checks both image banks and a protected rollback floor. It writes payload before header into the inactive bank, verifies readback and advances the floor before handoff. Tests interrupt every write boundary and selected torn writes. There is no filesystem, OpenPGP parser, USB or network updater in the model. Manufacturing-time immutability and secure-element counter atomicity are assumed interfaces.

Three onboard entropy source interfaces model the MCU and two secure elements. At least two sources must pass basic stuck/uniform checks; a protected generation prevents accepted counter rollback. The phone is never a source. Hash conditioning and sanity checks cannot establish actual entropy quality, independence or resistance to adversarial correlation. Host calls use OS randomness; all ARM diagnostic randomness and keys are public fixtures.

## Embedded evidence boundary

The trusted crates build without `std`. A separately linked Cortex-M33 ELF executes the real codec, encrypted records, fragmentation, jitter/playout and selected enrollment, invitation, storage, entropy and boot/update policy paths on QEMU MPS2 AN505. Its linker and runner enforce STM32U585-class capacity limits. This is not an STM32 peripheral model. The report includes static state, reserved heap/stack, an observed stack watermark and space for future drivers/partial display rendering. It does not establish worst-case stack, real-time 20 ms execution, hardware RNG quality, TrustZone isolation, BLE behavior or acoustic security.
